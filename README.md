# Предсказание стоимости подержанных автомобилей

Учебный проект по датасету Used Car Prices. Задача — регрессия: предсказание цены автомобиля (`price`) по его характеристикам. Исследование ведётся в `research.ipynb` в Google Colab.

## Выбранные модели и метрики

- **LinearRegression (OLS)** — линейная регрессия без регуляризации.
- **Ridge** — линейная регрессия с L2-регуляризацией и подбором `alpha`.
- **DecisionTreeRegressor** — дерево решений для регрессии.

Основная метрика для сравнения — **MAE**. Дополнительно оцениваем **RMSE** и **R²**.

## Гипотезы исследования

Гипотезы сформулированы после первичного знакомства со структурой данных и до подробного EDA и обучения моделей.

1. **OLS покажет меньшую MAE, чем дерево решений.** Предполагаем, что зависимости цены от характеристик автомобиля достаточно хорошо описываются линейной моделью.

2. **Ridge с подобранным `alpha` покажет меньшую MAE, чем OLS.** Предполагаем, что регуляризация поможет справиться с мультиколлинеарностью признаков.

3. **Удаление коррелирующих признаков сократит их количество без существенного изменения качества OLS.** Удаляем один признак из каждой пары входных признаков с корреляцией `|r| > 0.7` и сравниваем MAE до и после удаления.

4. **Исключение `accident`, `model_year` и `clean_title` незначительно изменит качество предсказания цены**, несмотря на важность истории аварий, года выпуска и статуса документов при покупке автомобиля. Проверяем совместное удаление всех трёх признаков.

5. **При глубине дерева больше 5 начнётся переобучение:** MAE на обучающих данных будет уменьшаться, а средняя MAE на кросс-валидации — увеличиваться.

6. **Ridge, обученная на логарифме цены, покажет меньшую MAE, чем Ridge, обученная на исходной цене.** Перед оценкой преобразуем прогнозы обратно в доллары, чтобы сравнить MAE в одинаковых единицах.

## Проверка гипотез

Сравниваем варианты на одинаковых разбиениях данных. Предобработку, отбор признаков и подбор гиперпараметров проводим на обучающих данных внутри кросс-валидации. Тестовую выборку используем для итоговой оценки.

При проверке удаления признаков сохраняем одну и ту же модель, настройки и обработку остальных признаков. Числовой порог для «незначительного изменения» заранее не задаём: в выводах приведём фактические изменения MAE.
